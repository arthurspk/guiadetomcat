## :dart: O guia para alavancar a sua carreira

> O Apache Tomcat é o servidor de aplicação Java mais usado do mundo: um container de Servlets e JSP open source, mantido pela Apache Software Foundation, que roda por trás de boa parte dos sistemas corporativos brasileiros — bancos, governo, seguradoras e varejo — e que também é o servidor embarcado por padrão em toda aplicação Spring Boot. Este guia reúne documentação oficial, cursos, livros, ferramentas, projetos práticos e um capítulo dedicado a usar IA na prática com o Tomcat — tudo verificado e organizado para quem quer sair do zero até administrar um servidor de aplicação Java em produção, com deploy de WAR, HTTPS, clustering e segurança configurados corretamente.

## 🗺️ Roadmap

- [Apache Tomcat — página oficial do projeto](https://tomcat.apache.org/) — Portal oficial da Apache Software Foundation, com downloads, documentação e notícias de cada versão.
- [Which version do I want? (documentação oficial)](https://tomcat.apache.org/whichversion.html) — Página oficial que explica a diferença entre as séries 9, 10.1 e 11 e ajuda a escolher qual usar em cada projeto.
- [Apache Tomcat — FAQ (Wiki oficial)](https://cwiki.apache.org/confluence/spaces/TOMCAT/pages/103098750/FAQ) — Perguntas frequentes mantidas pela própria comunidade do projeto.
- [roadmap.sh — Java Roadmap](https://roadmap.sh/java) — Trilha da comunidade para a linguagem Java; o Tomcat aparece como o container de Servlets padrão antes de frameworks como o Spring.
- [Apache Tomcat (Wikipédia, em inglês)](https://en.wikipedia.org/wiki/Apache_Tomcat) — Histórico do projeto desde 1999, arquitetura (Catalina, Coyote, Jasper) e adoção ao longo do tempo, com fontes.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos de Java e da Web** — JDK, HTTP, o que é um Servlet e o que é um container de Servlets.
2. **Instalação e primeira execução** — baixar o Tomcat, rodar `startup.sh`/`startup.bat` e acessar `http://localhost:8080`.
3. **Estrutura de uma aplicação web Java** — WAR, `web.xml`, diretório `WEB-INF`, Servlets e JSP.
4. **Deploy** — copiar um WAR para `webapps/` ou usar a aplicação Manager para publicar sem reiniciar o servidor.
5. **Configuração do servidor** — `server.xml`, `context.xml`, Connectors, Hosts e Realms (autenticação).
6. **Segurança e HTTPS** — TLS no Connector, `tomcat-users.xml`, hardening seguindo o guia oficial de segurança.
7. **Produção** — logging, monitoramento via JMX, pool de conexões JDBC via JNDI, proxy reverso com Nginx/Apache na frente.
8. **Escala** — clustering, balanceamento de carga e, quando fizer sentido, migrar para o Tomcat embarcado do Spring Boot.

Seu primeiro deploy em poucos minutos:

```bash
# baixe e descompacte o Tomcat (ajuste a versão conforme tomcat.apache.org/download-11.cgi)
curl -LO https://dlcdn.apache.org/tomcat/tomcat-11/v11.0.25/bin/apache-tomcat-11.0.25.tar.gz
tar xzf apache-tomcat-11.0.25.tar.gz
cd apache-tomcat-11.0.25

# suba o servidor
sh bin/startup.sh

# em outro terminal, confirme que está no ar
curl -I http://localhost:8080/
```

```bash
# derrube o servidor quando terminar
sh bin/shutdown.sh
```

## 🚀 Por onde começar

1. **Instale um JDK LTS atual** ([Adoptium — Eclipse Temurin](https://adoptium.net/pt-BR)), pré-requisito para rodar o Tomcat.
2. **Leia a introdução oficial** em [Introduction (documentação oficial)](https://tomcat.apache.org/tomcat-11.0-doc/introduction.html) para entender o que é Catalina, Coyote e Jasper.
3. **Baixe e rode o Tomcat localmente** seguindo o [Quick Start (RUNNING.txt, oficial)](https://tomcat.apache.org/tomcat-11.0-doc/RUNNING.txt) ou o [Setup (documentação oficial)](https://tomcat.apache.org/tomcat-11.0-doc/setup.html).
4. **Habilite o Manager App** com o [Manager App HOW-TO (oficial)](https://tomcat.apache.org/tomcat-11.0-doc/manager-howto.html) para publicar e remover aplicações pela interface web.
5. **Aprenda a fazer deploy de um WAR** com o [Deployer HOW-TO (oficial)](https://tomcat.apache.org/tomcat-11.0-doc/deployer-howto.html).
6. **Configure Connectors e HTTPS** com o [SSL/TLS Configuration HOW-TO (oficial)](https://tomcat.apache.org/tomcat-11.0-doc/ssl-howto.html).
7. **Endureça a instalação para produção** com o [Security Considerations (oficial)](https://tomcat.apache.org/tomcat-11.0-doc/security-howto.html).
8. **Pratique com um servlet real**, seguindo o [Servlets Tutorial (TutorialsPoint)](https://www.tutorialspoint.com/servlets/index.htm), e depois publique-o no seu Tomcat local.

## 🤖 IA na prática

O Tomcat é configurado majoritariamente por XML (`server.xml`, `context.xml`, `web.xml`) e por logs de texto estruturado — exatamente o tipo de conteúdo em que um assistente de IA ajuda bastante, desde que você valide o resultado reiniciando o servidor e observando o log, não apenas confiando no que a IA disse.

**Para aprender**
- Cole um trecho do seu `server.xml` ou `context.xml` e peça para a IA **explicar linha por linha** o que cada elemento (`Connector`, `Realm`, `Valve`, `Context`) faz — é mais rápido que caçar cada um na documentação oficial.
- Peça para a IA **gerar um `web.xml` ou uma classe `HttpServlet` de exemplo** a partir de uma descrição em português (ex.: "um servlet que recebe um formulário e responde em JSON") e rode no seu Tomcat local para confirmar.
- Peça exercícios práticos: "monte um cenário de deploy com dois `Context` diferentes no mesmo `Host` e peça para eu escrever a configuração, depois corrija o que eu errar".

**Para trabalhar**
- Use assistentes de código como [GitHub Copilot](https://github.com/features/copilot), [IntelliJ IDEA com AI Assistant](https://www.jetbrains.com/idea/) ou o [Claude Code](https://code.claude.com/docs/en/overview) para gerar blocos de `Connector`, regras de `Valve` e configurações de `Realm`/JNDI DataSource a partir de uma descrição em linguagem natural.
- Cole uma exceção do `catalina.out` (ex.: `OutOfMemoryError`, `ClassNotFoundException`, `PermGen`) e peça à IA para explicar a causa provável e sugerir o ajuste de configuração ou de código que resolve — mas sempre confirme na documentação oficial antes de aplicar em produção.
- **Sempre** teste a configuração em um ambiente de homologação e reinicie o Tomcat (`shutdown.sh` / `startup.sh`) depois de qualquer mudança sugerida por IA, observando o `catalina.out`, antes de aplicar em produção.

**Limites e boas práticas**
- A IA erra em detalhes específicos de versão — sintaxe de configuração que mudou entre o Tomcat 9 (namespace `javax.servlet`) e o 10.1/11 (namespace `jakarta.servlet`) é um erro comum. Confirme sempre no [guia oficial de migração](https://tomcat.apache.org/migration.html).
- Ela tende a sugerir Connectors e Realms sem endurecimento de segurança (usuário/senha padrão, TLS fraco). Peça explicitamente por configuração alinhada ao [Security Considerations oficial](https://tomcat.apache.org/tomcat-11.0-doc/security-howto.html).
- Nunca cole senhas do `tomcat-users.xml`, certificados privados ou dados de clientes reais em uma ferramenta de IA sem verificar a política de privacidade da sua empresa.
- Entenda o que você está aplicando: em um servidor de produção, cada elemento de configuração aceito é sua responsabilidade.
